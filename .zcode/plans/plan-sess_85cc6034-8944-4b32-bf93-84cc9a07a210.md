# Plan: Templates para Databases (Notion-style)

Feature full-stack siguiendo el modelo mental del spec entregado: **un Template es un factory que produce una nueva página (fila) por deep-copy**, sin sincronización posterior. Decisiones ya confirmadas contigo:
- **Alcance**: full-stack (backend + frontend + tests e2e), sin automations ni synced blocks.
- **Storage**: la "Page oculta" del template guarda los bloques; reusamos el CRUD de Block existente.
- **UX**: botón "+ New row" → dropdown (vacío / templates); template por defecto se auto-aplica.
- **Ocultamiento**: nuevo flag `is_template` en `Page` + filtros en 3 puntos.
- **Defaults**: todos los tipos editables (skip formula/rollup/system).

---

## Slice 1 — Modelo de datos + migración

**`backend/prisma/schema.prisma`**
- Añadir a `Page`: `is_template Boolean @default(false)`.
- Nuevo modelo:
  ```prisma
  model Template {
    id            String   @id @default(cuid())
    database_id   String
    name          String   @default("")
    icon          String?
    page_id       String   // → Page oculta (is_template=true) que guarda los bloques
    default_values Json    @default("{}")  // { property_id: value }
    is_default    Boolean  @default(false)
    created_by    String
    created_at    DateTime @default(now())
    updated_at    DateTime @updatedAt

    database Database @relation(fields: [database_id], references: [id], onDelete: Cascade)
    page     Page     @relation(fields: [page_id], references: [id], onDelete: Cascade)

    @@index([database_id])
    @@map("templates")
  }
  ```
- Relación inversa en `Database`: `templates Template[]`.
- Relación inversa en `Page`: `template_of Template[] @relation("TemplateBodyPage")` con el side correspondiente `page Page @relation("TemplateBodyPage")` en Template (la Page oculta apunta a un único Template; evita borrados accidentales y deja trazabilidad).

**Migración** `backend/prisma/migrations/20260802020000_templates/migration.sql` (siguiendo la convención `YYYYMMDDHHMMSS_nombre`):
- `ALTER TABLE pages ADD COLUMN is_template BOOLEAN NOT NULL DEFAULT false;`
- `CREATE TABLE templates (...)` con FKs a `databases` y `pages` `ON DELETE CASCADE`.
- (Índice en `database_id`.)

`npx prisma migrate dev` + `prisma generate`.

## Slice 3 — Backend: servicio de templates

Nuevo archivo **`backend/src/modules/databases/templates.service.ts`** (mantiene templates junto al módulo de databases, coherente con la estructura). Funciones:

- `createTemplate(databaseId, userId, { name, icon })`:
  - EDITOR access vía `getAccessiblePage(db.page_id)`.
  - En una transacción: crea la **Page oculta** (`is_template: true`, `workspace_id`, `parent_id: null`, `title: name`, `created_by`) → crea el `Template` (`page_id` → esa page, `default_values: {}`, `is_default` = true si es el primer template del db, si no false). Devuelve `TemplateDTO`.
- `listTemplates(databaseId)` → `TemplateDTO[]`.
- `getTemplate(templateId)` (con access check).
- `updateTemplate(templateId, userId, { name, icon, is_default, default_values })`:
  - EDITOR access. Si `is_default: true`, en una tx desmarca los demás templates del mismo db (sólo uno por default).
  - `default_values`: valida que cada `property_id` pertenece al db y que el tipo es editable (no formula/rollup/created_*/last_edited_*); los demás se aceptan tal cual (no hay normalización per-tipo hoy, igual que `updatePropertyValue`).
- `deleteTemplate(templateId, userId)`: OWNER access (como `deleteDatabase`). Borra el Template + su Page oculta (cascade de bloques vía FK).

**`backend/src/modules/databases/databases.service.ts`** — `addRow` extendido:
- Nueva firma `addRow(databaseId, userId, opts?: { templateId?: string | null })`.
- Resuelve el template a aplicar (explícito, o el `is_default` del db si existe, o ninguno).
- En una transacción (mismo `row_order = max+1` actual), crea la Page-row. **Si hay template**: copia los bloques (reusando el loop `idMap` del `duplicatePage` existente, adaptado a `tx`), hace upsert de los `default_values`, y si hay un default para la propiedad "Name" sincroniza `page.title`.
- Devuelve `{ page_id, title }` (mismo shape actual — no rompe la API).

Helper interno `cloneBlocks(tx, srcPageId, dstPageId, userId)` extraído de la lógica de `duplicatePage` para reusar sin duplicar.

**`toDatabaseDTO`** (`databases.dto.ts`) + la 4 llamadas: añadir `templates?` opcional y mapear con `toTemplateDTO`. En `getDatabase` hacer include de templates.

## Slice 4 — Backend: rutas, controladores, schemas

**`databases.schema.ts`**: `createTemplateSchema`, `updateTemplateSchema` (zod, mismo estilo), `createRowSchema { template_id: z.string().nullable().optional() }`.

**`databases.controller.ts`**:
- `addRowHandler`: parsear `createRowSchema`, pasar `opts` al servicio.
- Nuevos handlers: `listTemplatesHandler`, `createTemplateHandler`, `updateTemplateHandler`, `deleteTemplateHandler`, `getTemplatePageHandler` (devuelve page+blocks de la page oculta para el editor), `updateTemplatePageBlockHandler` (delegar al blocks service — o reutilizar el router de blocks existente ya que los bloques viven en una Page real). **Decisión:** los bloques del template se editan con el CRUD de blocks **existente** (`/api/v1/blocks`, que opera por `page_id`) — no se reimplementa. Sólo hay que permitir EDITOR-access sobre la page oculta vía `getAccessiblePage` encadenando template→database→host page.

**`databases.routes.ts`** (bajo `databasesRouter`):
```
GET    /databases/:databaseId/templates
POST   /databases/:databaseId/templates
GET    /databases/:databaseId/templates/:templateId
PATCH  /databases/:databaseId/templates/:templateId
DELETE /databases/:databaseId/templates/:templateId
```
Las rutas de bloques del template reusan `/api/v1/blocks` existente (la page oculta es una Page normal con `is_template=true`).

## Slice 5 — Exclusión de la Page oculta (3 puntos)

Según el reporte del agente, insertar `is_template: false`:
1. `pages.service.ts` `listChildPages` — el `findMany` (línea 23-28) **y** el `groupBy` de `has_children` (32-39).
2. `search.service.ts` — la SQL cruda (línea 39-41): `AND is_template = false`.
3. `pages.service.ts` `getPageAncestors` — filtrar al construir `chain` (skip si el ancestor tiene `is_template=true`), o `break` el walk (una page oculta no debe aparecer en breadcrumbs).

`getDatabase` (filas) **no** necesita cambio: la page oculta tiene `database_id=null` → ya excluida.

## Slice 6 — Frontend

**`frontend/src/api/databases.ts`**:
- Extender `addRow(databaseId, body?)` para enviar `{ template_id }`.
- Nuevas: `listTemplates`, `createTemplate`, `updateTemplate`, `deleteTemplate`.

**`frontend/src/components/db/views/TableView.tsx`** — el botón "+ New row" se vuelve un dropdown:
- Si `db.templates?.length`: menú con "New row" (vacío) + lista de templates. Si hay `is_default`, la primera opción "New row" aplica ese template (auto-aplicado estilo Notion).
- Si no hay templates: botón simple como hoy.
- "Edit templates" → abre un modal/panel con la lista de templates (crear, renombrar, marcar default, eliminar) y cada uno con un botón "Edit content" que abre el Editor sobre la page oculta (`template.page_id`).

**Editor del template**: reutilizar el `Editor` existente + `PageView` apuntando a `template.page_id` (es una Page normal). Se accede desde el modal de templates; al cerrar se invalida `["database", db.id]`.

Nuevos tipos importados desde `@notion-clone/shared` (`TemplateDTO`).

## Slice 7 — Tests e2e + spec

**Spec** `specs/016-database-templates/` (`spec.md`, `tasks.md`) siguiendo el formato de `014-databases-v2` y `003`. Documenta el modelo mental del factory, endpoints, y out-of-scope (automations, synced blocks).

**`frontend/tests/e2e/databases.spec.ts`** (o un `templates.spec.ts` nuevo) — casos:
- Crear template → aparece en la lista del db.
- Editar contenido del template (añadir bloque) → persiste.
- Crear fila vacía (sin template) → page vacía (regresión).
- Crear fila desde template → los bloques del template se copian a la nueva row; defaults aplicados.
- Template por defecto → "New row" lo aplica automáticamente.
- Editar la row instanciada NO modifica el template (independencia).
- Editar el template NO modifica rows ya creadas.
- La page oculta NO aparece en sidebar/search/breadcrumbs.
- Eliminar template → OK (OWNER); no afecta rows creadas.
- Access: VIEWER no puede crear/editar template (403).

## Notas / no-roturas
- `addRow` mantiene su signature anterior (opts opcional) y el mismo return shape → frontend viejo sigue funcionando.
- `DatabaseDTO.templates` es opcional → las 4 llamadas a `toDatabaseDTO` no se rompen.
- Reutilización clave: CRUD de blocks existente para editar el cuerpo del template; loop `idMap` de `duplicatePage` para la copia al instanciar.
- No se introducen variables dinámicas ({{today}} etc.) en este slice — fuera del alcance acordado.
